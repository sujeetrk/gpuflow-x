# GPUFlow-X

## AI-Driven Self-Learning Inference Scheduler

GPUFlow-X is an experimental, CPU-validated inference-scheduling research project. It explores dynamic batching, priority queues, deadline/SLA-aware scheduling, workload prediction, self-learning policy updates, telemetry, and scheduler benchmarking.

> **Current implementation note:** The scheduler, predictors, learning policy, and inference service are currently implemented in Python. The existing C++ target is a minimal readiness executable; it is not yet integrated into the Python scheduler. CUDA/GPU execution and GPU telemetry are not currently validated. Do not interpret the project name as proof of GPU acceleration.

## Project status

- Phases 0–9: implemented in the current project history; Phase 9 includes priority and SLA/deadline-aware scheduling.
- Phase 9 audit: dependency declaration, learning attribution, error isolation, benchmark coverage, and documentation are being stabilized.
- Phase 10: planned C++/Python integration, to be reported complete only after implementation and tests.

## Current architecture

```text
Inference requests
       |
       v
Priority/deadline request queue
       |
       v
AI scheduler <---- Workload predictor (scikit-learn)
       |           Self-learning policy (contextual bandit)
       v
Deadline-aware dynamic batch collector
       |
       v
Inference service / CPU backend (PyTorch)
       |
       v
Request status + telemetry + reward/policy update
```

The current AI scheduler combines model-based workload prediction with a tabular epsilon-greedy self-learning policy. Deadline guards may override proposed batching decisions. Telemetry and policy persistence are auxiliary to request execution.

## Repository map

- `core/queue/` — request queue and request metadata
- `core/batching/` — batch representation, configuration, and collection
- `core/scheduler/` — FIFO, adaptive, and AI-driven schedulers
- `core/policy/` — prediction-driven policy, reward calculation, and self-learning policy
- `ai/` — workload/latency predictor training and inference
- `inference/` — PyTorch inference service and CPU backend
- `benchmark/` — scheduler comparison and workload benchmark utilities
- `core/main.cpp`, `CMakeLists.txt` — minimal C++ executable (not yet a Python extension)

## Setup (WSL/Linux)

Use a supported Python environment and install the declared dependencies:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

The predictor tests and AI scheduler require the trained model artifacts below. They are generated by the training scripts and may be excluded from source archives because they are binary files.

```bash
python -m ai.workload_predictor.train
python -m ai.latency_predictor.train
```

Training requires the corresponding CSV datasets in `ai/workload_predictor/` and `ai/latency_predictor/`. Ensure those datasets are present before running the commands. Then run:

```bash
python -m pytest -q
```

## Benchmark

Run the Phase 9 comparison from the repository root:

```bash
python -m benchmark.compare_schedulers
```

The benchmark uses equivalent freshly-created request workloads and compares FIFO, Adaptive, fixed AI, and learning-enabled AI scheduling. It reports completion/failure counts, throughput, average and P95 latency, deadline misses, and batch count. The learning-enabled variant starts from a clean temporary policy file per run. Results depend on host load, Python/PyTorch/scikit-learn versions, model artifacts, and workload timing; rerun locally and report measured output rather than treating stored numbers as universal performance claims.

## Known limitations

- Current inference validation is CPU-side; no NVIDIA GPU/CUDA performance claim is made.
- GPU utilization and VRAM metrics are placeholders in the current scheduler state.
- The C++ executable is not yet connected to the Python scheduling path.
- Synthetic/local benchmark results are not production workload guarantees.
- Serialized scikit-learn models can be version-sensitive; retrain with the declared environment if loading produces compatibility warnings or errors.

## Phase 10: Multi-GPU Intelligent Scheduler

GPUFlow-X now includes GPU-aware inference placement and load balancing.

### Implemented
- GPU device discovery through PyTorch CUDA availability.
- Least-loaded GPU selection with rotating tie-breaking.
- Per-GPU inference backends and model instances.
- CPU fallback when no CUDA GPUs are available.
- Thread-safe assignment tracking and release.
- Device assignment cleanup after successful or failed inference.
- Multi-GPU placement and load-balancing tests.

### Validation
- Device manager and placement tests.
- Simulated multi-GPU inference service tests.
- 10,000-request simulated load-balancing benchmark.
- Full project regression test suite.

Note: Multi-GPU placement tests use simulated devices on CPU-only
systems. Actual multi-GPU inference performance requires compatible
NVIDIA GPUs, CUDA, and a suitable PyTorch installation.
The benchmark measures assignment throughput, not GPU inference speed.
